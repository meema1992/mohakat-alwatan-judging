# منصة تحكيم محاكاة الوطن تجمعنا — نسخة Firebase Spark المجانية

## ما الذي تغيّر؟
هذه النسخة لا تستخدم Cloud Functions ولا تتطلب الترقية إلى Blaze أو ربط بطاقة. تسجيل دخول المحكّمين أصبح عبر حسابات Firebase Authentication (البريد الإلكتروني وكلمة المرور). لا تستخدمي رموز PIN القديمة.

## الملفات
- `index.html`, `styles.css`, `app.js`: واجهة عربية متجاوبة.
- `firebase-config.example.js`: قالب إعداد Firebase؛ انسخيه إلى `firebase-config.js` وضعي بيانات Web App.
- `firestore.rules`: قواعد صلاحيات الإدارة والمحكّمين.
- لا حاجة إلى Firebase CLI أو مجلد functions في هذه النسخة.

## إعداد Firebase مرة واحدة
1. من Authentication > Sign-in method فعّلي Email/Password.
2. أنشئي حساب الإدارة في Authentication إذا لم يكن موجودًا، ثم في Firestore أنشئي `users/{UID}` (معرّف المستند هو UID نفسه) بالحقول:
   - `role` (string) = `admin`
3. لكل محكّم: أنشئي له حسابًا مستقلًا في Authentication باستخدام بريده وكلمة مرور مؤقتة/متفقًا عليها. انسخي UID الخاص به، ثم أنشئي مستندًا في مجموعة `users` ومعرّف المستند هو UID، وأضيفي:
   - `role` (string) = `judge`
   - `name` (string) = اسم المحكّم
   - `active` (boolean) = `true`
   أرسلي بيانات الدخول للمحكّم بشكل خاص، واطلبي منه تغيير كلمة المرور بعد أول دخول إذا رغبتِ.
4. انسخي `firebase-config.example.js` إلى `firebase-config.js`، وضعي قيم إعدادات Web App من Firebase. لا تضعي كلمة مرور أي حساب في هذا الملف.
5. انشري قواعد `firestore.rules` من Firebase Console > Firestore Database > Rules. لا تحتاجين Firebase CLI.
6. ارفعي ملفات النسخة الجديدة إلى مستودع GitHub نفسه، مع استبدال الملفات القديمة. لأن الموقع يعمل عبر GitHub Pages، يجب أن يكون ملف `firebase-config.js` ضمن ملفات الموقع المرفوعة إلى المستودع حتى يستطيع المتصفح الاتصال بـ Firebase. إعداد Web App الظاهر في هذا الملف ليس كلمة مرور ولا يمنح وحده صلاحية الوصول؛ الحماية الفعلية بقواعد Firestore وحسابات المستخدمين. لا تضعي في الملف كلمات مرور أو مفاتيح خادم أو بيانات سرية.

## التشغيل والإدارة
- المشاركون الذين حالتهم `not_submitted` يظهرون في قائمة الإدارة ولا يظهرون ضمن قائمة التقييم.
- حالة `account_suspended` لا تمنع التقييم ما دامت المشاركة مستوفية.
- كل محكّم يملك مستند تقييم واحدًا لكل مشارك؛ تعديل الدرجات يحدّث المستند نفسه ولا يكرر التقييم.
- 4 محاور × 4 معايير × 6 درجات = 96 درجة خام.
- الدرجة المحوّلة = (مجموع المحكّم ÷ 96) × 100.
- النتيجة النهائية = متوسط الدرجات المحوّلة لكل المحكّمين الذين قيّموا المشارك بعد بلوغ الحد الأدنى المطلوب.
- من لوحة الإدارة حددي عدد المحكّمين المطلوب لكل مشارك. لن يسمح زر النشر بنشر النتائج إذا كان عدد المحكّمين الذين قيّموا أي مشارك مستوفٍ أقل من العدد المحدد. وإذا زاد العدد، تُحتسب جميع التقييمات الصحيحة الفريدة.
- النشر يتم عند ضغط الإدارة على زر النشر بعد اكتمال التقييمات، وليس تلقائيًا.

## تنبيه مهم
هذه نسخة مناسبة لخطة Spark ولا تستخدم خادمًا مدفوعًا. احتفظي بحساب الإدارة وكلمات المرور سرية، ولا تمنحي دور `admin` لأي محكّم. قواعد Firestore تمنع المحكّم من تعديل تقييم شخص آخر أو الكتابة في النتائج العامة.
